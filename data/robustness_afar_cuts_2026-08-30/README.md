# Panel 3 (A_far) — topic-cut robustness grid, 2026-08-30

## Why

Until 2026-08-30 the paper's Panel 3 kept pairs whose minimum similarity dose was at or
above the discipline's median positive dose. A design-history search on 2026-08-30 found
**no recorded argument for that cut**: what was argued in August 2026 was a
per-discipline quantile versus a single absolute number, never "median versus any
positive overlap", and the author never commented on it. The
2026-08-17 grid that did span cuts was run **without** the network condition, so
no A_far estimate existed at any cut other than the median. The author asked for
the grid on 2026-08-30.

## What was run

`analysis/robustness/p3_afar_cuts/build_afar_cut.py` rebuilds the A_far cell with
the threshold as a parameter. Every panel-building SQL statement is byte-for-byte
`analysis/robustness/p3_afar/build_afar.py`'s; only the threshold line differs.

| cut_spec | predicate on `dmin = least(dose_i, dose_j)` |
|---|---|
| `pos`   | `dmin > 0` — both incumbents share at least one subfield with the star |
| `med`   | `dmin >= q50(dose>0)` — the paper's cut until 2026-08-30; now the control cell |
| `abs04` | `dmin >= 0.4` |
| `p75`   | `dmin >= q75(dose>0)` |

Estimator: `analysis/estimation/run_p3_tp.R`, unchanged, same spec as the paper
(group = pair x event, D = post, effects = 5, placebo = 4).

## One structural fact found on the way

The cut is the median of the **individual** dose distribution, applied to the
**pair** minimum. It therefore keeps 26.9 percent of positive-overlap econ pairs,
not half of them: among A_far candidates with `dmin > 0`, the quartiles of `dmin`
are 0.102 / 0.207 / 0.350, so the 0.334 threshold sits near the 73rd percentile of
the pair distribution. The thesis wording ("at or above the median positive dose")
describes how the number is computed and is accurate, but a reader may take it to
mean half the pairs survive.

## Addendum — the cut is now pinnable, and the pin has to be full precision

The audit's other open item (causal-gap audit, A3 item 2) was that the median is recomputed at
build time, so it moves whenever the dose table moves: the 2026-08-28 caliber change shifted it
econ .3332 -> .3340, chem .3427 -> .3388, math .0885 -> .0897, silently changing which pairs are
in the panel. `build_afar_cut.py` now takes `fixed:<value>`, and `PIN_CANON` holds the values the
canonical frames were actually built with.

**A rounding trap found on the way.** Pinning at the 4-dp values printed in
`data/frames/p3_afar_counts.csv` does NOT reproduce the frozen frames: math_stats gains 24 pairs
(2,794 against the frozen 2,770) and 408 rows, because its dose distribution is dense right at
the threshold. Any pin must carry the full double:

| field | pinned value | rebuild vs frozen frame |
|---|---|---|
| econ | 0.33404650205120173 | 393,007 rows / 23,758 pairs / 1,074 ties / 86 events — exact |
| chemistry | 0.338776171207428 | 39,242 / 2,466 / 266 / 33 — exact |
| math_stats | 0.08974236053931156 | 46,010 / 2,770 / 106 / 31 — exact |

So pinning is a no-op against today's canon and a guarantee against the next event-set change.
Whether the CANONICAL builder (`analysis/robustness/p3_afar/build_afar.py`) should be switched
from the live median to the pin is an identification-layer call and is left to the author.
